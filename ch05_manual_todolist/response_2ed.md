# 两个问题的建议方案

## 1. 待办内容支持修改 ✅

**做法**：把 `PATCH /api/todos/:id` 改成**通用部分更新**接口，`title` 和 `completed` 都可以传，传哪个改哪个。

**API 调整**：

| 方法   | 路径             | 功能         | 请求体（任选其一或都传）          | 返回   |
| ------ | ---------------- | ------------ | --------------------------------- | ------ |
| PATCH  | `/api/todos/:id` | 更新待办     | `{ title?, completed? }`          | `Todo` |

**使用场景**：
- 打钩 → `PATCH /api/todos/5`  body: `{ completed: true }`
- 改文字 → `PATCH /api/todos/5`  body: `{ title: "买酸奶" }`
- 同时改 → 两个字段都传

**数据库**：顺便加个 `updatedAt` 字段，记录最后修改时间（每次 PATCH 自动更新），方便以后排序或显示"刚改过"。

**前端交互**：
- 双击待办文字 → 进入编辑态（变成输入框）
- 回车 / 失焦 → 保存
- Esc → 取消

---

## 2. 排序规则：未完成在上、已完成在下 ✅

**理由**：
- 这是 TODO 类应用的**主流做法**（Things、滴答清单、微软 TODO 都是这种）
- 已完成的事项视觉上"沉底"，符合"做完就翻篇"的心理预期
- 用户每次打开主要关心"还有啥没做"，未完成置顶最直接

**具体规则**（两级排序）：
1. **第一级**：`completed = 0`（未完成）在前，`completed = 1`（已完成）在后
2. **第二级**：组内按 `createdAt DESC`（新的在上面）

**对应 SQL**：
```sql
SELECT * FROM todos ORDER BY completed ASC, createdAt DESC;
```

**视觉效果**：
```
─────────────────────
☐ 买酸奶          (新)
☐ 写周报
☐ 看医生          (老)
─────────────────────
☑ 买牛奶          (新完成)
☑ 取快递          (老完成)
```

## 更新后的数据模型

| 字段       | 类型                              | 说明                      |
| ---------- | --------------------------------- | ------------------------- |
| id         | INTEGER PRIMARY KEY AUTOINCREMENT | 主键                      |
| title      | TEXT NOT NULL                     | 待办内容                  |
| completed  | INTEGER (0/1)                     | 完成状态                  |
| createdAt  | TEXT                              | 创建时间 ISO 字符串       |
| updatedAt  | TEXT                              | **新增** · 最后修改时间   |
